## Review Focus

1. **A held or repeated key approves once.** Holding `A` or double clicking Approve must produce one approval and one toast. Test in Task 15 (`approve fires once on key repeat`).
2. **Typing in the editor never triggers single-key actions.** `a`, `s`, `j`, `x`, `g` typed in the subject or body only type. Test in Task 6 (`single keys are ignored while typing`) and Task 15 (`typing a in the body does not approve`).
3. **An undoable write is not lost when he leaves.** A pending write (inside its 8-second undo window) commits on route change and on `pagehide`, never silently drops. Test in Task 8 (`flushes pending writes on pagehide`).
4. **A refresh does not move what he is looking at.** When polling returns the selected item in a new group, the selected row stays where it was until the selection moves. Test in Task 9 (`keeps the selected item in place across a refresh`) and Task 14 (`selected row stays put after it is approved`).
5. **Recipient times survive time zones and DST.** "10:42 ET" and "Fri Oct 30, 10:02 PT" come from UTC plus an IANA zone; the fixture spans the Nov 1 2026 DST change. Test in Task 9 (`formats recipient time across the DST change`).

## Undo, without inverse endpoints

Every reversible action (pick, unpick, backlog, approve, skip, mark ok, log a LinkedIn step, set reply tag) goes through `usePendingWrite` (Task 8). It updates the TanStack Query cache at once, shows the Sonner toast with Undo and `Z`, and calls the client only when the 8-second window ends, when another route loads, or on `pagehide`. Undo inside the window drops the call. So the API needs no undo endpoints and the append-only tables (`linkedin_log`, `event`) never need a retraction. After the window, the normal opposite action applies (unapprove, unpick). Dialog actions (remove, close, no-go, lift no-go, resume) commit at once.

3. Add `src/api/http/client.ts` implementing `OutreachClient` with `fetch`: `Idempotency-Key` header from `requestId`, `revision` in the body, HTTP 409 to `conflict`, the approve refusal to `blocked` with its checks. `createClient()` picks it when `import.meta.env.VITE_API === 'http'`.
4. `vite.config.ts` gains `server.proxy['/api'] = 'http://127.0.0.1:3100'`; production is served by FastAPI from `web/dist/` (#17 part B).
5. `FixtureClient` stays for unit tests and Playwright; the e2e suite gains a second project that runs against a staging import (#17 part A) on a scratch `OUTREACH_DB`.
6. What the store needs for these types (from the spec's section 15 and this plan's `// needs #4 0002` marks): the five reply tags, LinkedIn reason, remove reasons, a stored mail-server check per domain, and the global pause with a hard-block message. ## Decisions for Devanshu

Each has a default this plan builds.

1. **Undo by waiting.** An approve, pick, skip or LinkedIn log takes effect 8 seconds after the click (or at once when he leaves the page), so Undo never has to reverse anything on the server. Default: yes. The other choice is instant writes plus undo endpoints in #11.
2. **Node 20.** #12 says Node 20; the newest React Router, Vitest and jsdom need Node 22, so this plan pins the last lines that run on 20. Default: stay on 20. Moving to Node 22 later is a version bump, not a rewrite.
3. **The five open questions in `docs/design/README.md` section 14** are built with their defaults (Claude's no-go waits for him, capacity goes to 10 at a limit of 60, removed companies can come back by hand, every reply gets a tag with Interested preselected, theme follows the Mac).
