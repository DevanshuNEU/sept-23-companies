# CI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every pull request and every push to master runs the Python tests, the mutation check, and the web lint, typecheck, unit tests, build and e2e on GitHub Actions, with a web unit suite that no longer depends on how fast the machine is.

**Architecture:** First make the web unit suite deterministic and prove it under artificial CPU load (Tasks 1 to 4), because a gate that flakes gets ignored. Then one workflow, `.github/workflows/ci.yml`, with five jobs (`python`, `mutation`, `web`, `e2e`, `ci-ok`). Path filtering is done inside the workflow by a `changes` job, not with workflow-level `paths:`, so a skipped mutation job never leaves a required check pending. One aggregate job, `ci-ok`, is the single check branch protection names.

**Tech Stack:** GitHub Actions on `ubuntu-latest`; `uv` with Python 3.14; Node 20.19.5 (from `web/.nvmrc`); pnpm 10.28.1 (from `web/package.json` `packageManager`); Vitest 4.1.12 with jsdom; React Testing Library 16; `@testing-library/user-event` 14.6.8; Playwright 1.64.1.

**Spec:** GitHub issue #34 and its comment of 2026-10-21 (`gh issue view 34 -R DevanshuNEU/sept-23-companies --comments`). Pinned decision record is issue #9; this plan changes no decision in it. Project rules: `CLAUDE.md` (Building, Live system).

**Branch:** `DevanshuNEU/ci-34` from master. One PR, body says it closes #34. Nothing here touches `mail/`, `refresh/`, `dashboard/` or `outreach/`.

## Global Constraints

- Python: `==3.14.*`, `python-preference = "only-system"` (pyproject), so CI must put a system 3.14 on PATH before `uv` runs. Standard library only in `mail/`, `refresh/`, `dashboard/`; `dependencies = []`.
- Python tests: `uv run python -m unittest discover -s tests -t .` from the repo root. `tests/__init__.py` sets scratch `OUTREACH_MAIL_HOME`, `OUTREACH_GMAIL_DIR`, `OUTREACH_DB`; CI sets none of them and never needs the real Gmail folder or the live store.
- Mutation check: `uv run python tests/mutation_check.py`, about 10 minutes locally. It exits 0 only when `caught N  missed 0  skipped 0`; it edits files in `outreach/rules` and `outreach/store` in place and refuses to run with those files dirty or in the live checkout (a CI checkout is neither).
- Web: Node `>=20.19.0 <21` (strict engines), `pnpm install --frozen-lockfile`, scripts `lint`, `typecheck`, `test` (sets `TZ=America/New_York`), `build`, `e2e`.
- Playwright: `workers: 1`, port from `WEB_PORT` (default 5173). Never 3001, 3002, 3011 or 3013. Local runs keep `channel: 'chrome'`.
- No secrets: the workflow uses none, `permissions: contents: read`, trigger is `pull_request` (never `pull_request_target`). CI never runs a refresh, a send, a crawl or the mail API.
- No `retries`, no `retry`, no `--retry` anywhere. A test that needs a retry to pass is a bug to fix.
- Tests first: write the test, watch it go red for the right reason, then make it green.
- No em dashes or en dashes in any file, comment, workflow, commit message or PR body.
- Commit trailer: the one the executing session is given.

## Review Focus

1. A docs-only or web-only PR: the mutation job is skipped and `ci-ok` is still green, never "pending" (Task 6 step 7 observes it on a real PR).
2. A new test directory without `__init__.py` (the pipeline plan adds `tests/pipeline/`) is silently not run by `unittest discover`; a guard test fails first (Task 5).
3. One test that fails under load leaves a fake clock or a toast behind and fails the next ones, so 2, 19 and 50 failures are one cause spread out; a guard test pins the cleanup (Task 2).
4. A slow runner makes the mutation check time out; `mutation_check.py` counts a timeout as CAUGHT, which would hide a weak test. The job fails if the log contains `TIMEOUT` (Task 6).
5. The mutation log written inside the repo would make the tree dirty and trip the check's own clean-tree refusal; the log goes to `$RUNNER_TEMP` (Task 6).

### Task 1: The load rig, and a red baseline

**Files:**
- Create: `web/scripts/under-load.sh`
- Modify: `web/package.json` (script `"test:load": "bash scripts/under-load.sh pnpm test"`)

**Interfaces:**
- Produces: `bash web/scripts/under-load.sh <command...>` runs `<command>` with `K` CPU burners alive (default `K = 3 x core count`, override with `LOAD_BURNERS=<n>`), kills them on exit (trap on EXIT, INT, TERM), exits with the command's status, prints `load average at start: ...` from `uptime`. Cores come from `getconf _NPROCESSORS_ONLN`. A burner is `yes > /dev/null`.
- Produces: `pnpm test:load` and the three-run proof loop used by Tasks 3 and 4.

- [ ] **Step 1: Write the script.** Burners start before the command and are verified alive (`kill -0`) once before it runs. Quote every variable; `set -u`.
- [ ] **Step 2: Check the rig kills its burners.** Run `bash web/scripts/under-load.sh true`, then `pgrep -x yes | wc -l`. Expected: `0`.
- [ ] **Step 3: Record the quiet baseline.** In `web`, run `pnpm test --reporter=json --outputFile=test-results/quiet.json` (the folder is gitignored). Expected: 500 of 500 pass. Extract the 15 slowest tests (title, file, ms) from the JSON with a one-line `node -e`, and keep the list in the PR body. Any test above 1500 ms on a quiet machine is a Task 4 candidate for splitting.
- [ ] **Step 4: Get a red baseline under load.** Run `LOAD_BURNERS=<n> pnpm test:load --reporter=json --outputFile=test-results/load-1.json` (flags after `pnpm test:load` reach vitest; do not add a `--`, on pnpm 10 it reaches vitest literally and the flags become file filters). Start at the default; if the suite is green, raise `LOAD_BURNERS` (4x, 5x cores) until at least one test fails, and record that value as `K_PROOF`. - [ ] **Step 5: Write the failure list per file.** From `load-1.json`, group failed test names by file and by message kind (5 s timeout, `waitFor` / `findBy` timeout, other). ### Task 6: The workflow

**Files:**
- Create: `.github/workflows/ci.yml`

**Interfaces:**
- Produces: check names `python`, `mutation`, `web`, `e2e`, `ci-ok`. Branch protection names only `ci-ok`.

Resolve action versions first: `gh api repos/actions/checkout/releases/latest --jq .tag_name` and the same for `actions/setup-python`, `actions/setup-node`, `actions/cache`, `actions/upload-artifact`, `astral-sh/setup-uv`, `pnpm/action-setup`; pin the major (`@v5` style) it returns. The majors in the YAML below are the expected ones.

- [ ] **Step 1: Write the workflow.**

```yaml
name: CI
on:
  pull_request:
  push:
    branches: [master]
permissions:
  contents: read
concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: ${{ github.event_name == 'pull_request' }}

jobs:
  changes:
    runs-on: ubuntu-latest
    timeout-minutes: 5
    outputs:
      mutation: ${{ steps.filter.outputs.mutation }}
    steps:
      - uses: actions/checkout@v5
        with: { fetch-depth: 0 }
      - id: filter
        env:
          BASE: ${{ github.event.pull_request.base.sha }}
          HEAD: ${{ github.event.pull_request.head.sha }}
        run: |
          if [ "$GITHUB_EVENT_NAME" != "pull_request" ]; then echo "mutation=true" >> "$GITHUB_OUTPUT"; exit 0; fi
          if git diff --name-only "$BASE" "$HEAD" | grep -Eq '^(outreach/|tests/|live_checkout\.py$|pyproject\.toml$|uv\.lock$|\.github/workflows/ci\.yml$)'; then
            echo "mutation=true" >> "$GITHUB_OUTPUT"
          else
            echo "mutation=false" >> "$GITHUB_OUTPUT"
          fi

  python:
    runs-on: ubuntu-latest
    timeout-minutes: 15
    steps:
      - uses: actions/checkout@v5
      - uses: actions/setup-python@v6
        with: { python-version: '3.14' }
      - uses: astral-sh/setup-uv@v7
        with: { enable-cache: true, cache-dependency-glob: uv.lock }
      - run: uv sync --frozen
      - run: uv run --frozen python -m unittest discover -s tests -t .

  mutation:
    needs: changes
    if: needs.changes.outputs.mutation == 'true'
    runs-on: ubuntu-latest
    timeout-minutes: 45
    steps:
      - uses: actions/checkout@v5
      - uses: actions/setup-python@v6
        with: { python-version: '3.14' }
      - uses: astral-sh/setup-uv@v7
        with: { enable-cache: true, cache-dependency-glob: uv.lock }
      - run: uv sync --frozen
      - name: Mutation check (must end with missed 0 and no timeouts)
        run: |
          set -o pipefail
          uv run --frozen python tests/mutation_check.py | tee "$RUNNER_TEMP/mutation.log"
          grep -Eq '^caught [0-9]+  missed 0  skipped 0$' "$RUNNER_TEMP/mutation.log"
          ! grep -q 'TIMEOUT' "$RUNNER_TEMP/mutation.log"

  web:
    runs-on: ubuntu-latest
    timeout-minutes: 20
    defaults: { run: { working-directory: web } }
    steps:
      - uses: actions/checkout@v5
      - uses: pnpm/action-setup@v4
        with: { package_json_file: web/package.json }
      - uses: actions/setup-node@v5
        with:
          node-version-file: web/.nvmrc
          cache: pnpm
          cache-dependency-path: web/pnpm-lock.yaml
      - run: pnpm install --frozen-lockfile
      - run: pnpm lint
      - run: pnpm typecheck
      - run: pnpm test
      - run: pnpm build

  e2e:
    runs-on: ubuntu-latest
    timeout-minutes: 25
    defaults: { run: { working-directory: web } }
    env:
      PW_BUNDLED: '1'
      WEB_PORT: '5173'
    steps:
      - uses: actions/checkout@v5
      - uses: pnpm/action-setup@v4
        with: { package_json_file: web/package.json }
      - uses: actions/setup-node@v5
        with:
          node-version-file: web/.nvmrc
          cache: pnpm
          cache-dependency-path: web/pnpm-lock.yaml
      - run: pnpm install --frozen-lockfile
      - uses: actions/cache@v4
        with:
          path: ~/.cache/ms-playwright
          key: playwright-${{ runner.os }}-${{ hashFiles('web/pnpm-lock.yaml') }}
      - run: pnpm exec playwright install --with-deps chromium
      - run: pnpm e2e
      - if: failure()
        uses: actions/upload-artifact@v4
        with:
          name: playwright-report
          path: |
            web/playwright-report
            web/test-results
          retention-days: 7

  ci-ok:
    if: always()
    needs: [python, mutation, web, e2e]
    runs-on: ubuntu-latest
    steps:
      - if: contains(needs.*.result, 'failure') || contains(needs.*.result, 'cancelled')
        run: exit 1
```

  Notes the file must keep: the `changes` job runs on every event so `mutation` never depends on a skipped job; `mutation` skipped counts as passing in `ci-ok`; the mutation log is outside the checkout so the tree stays clean (Review Focus 5).
