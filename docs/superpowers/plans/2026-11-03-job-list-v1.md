# Job list v1 Implementation Plan (Part of #156)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Browse page becomes the job list: tech postings at his level, newest first, with the facts he checks,
Pass and Go ahead on each row, and a Mac alert when a new one appears.

**Architecture:** One pure query module (`outreach/pipeline/joblist.py`) over postings, their current decision and
company facts; one cached read route `GET /api/jobs`; two write routes (pass, go ahead); the web page at the existing
`browse` route rebuilt around that read; an alert step at the end of the crawl tick. v1 uses today's decision columns.
The rules PR (#154) and the dates PR (#155) later sharpen the same views without changing the page.

**Tech Stack:** Python 3.14, SQLite, FastAPI, React with TanStack Query, `unittest`, vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-01-fresh-jobs-quiet-needs-you-design.md` Part D, and
`docs/superpowers/plans/2026-11-02-right-job-pipeline-master-plan.md` PR 5. Devanshu asked on 2026-11-03 01:30 for the
new job list live by 08:00; this v1 runs on today's data so it can ship before #154 and #155.

## Global Constraints

- His rule: the right job, at the right company, at the right time. He reads every posting himself: no fit score, no
  "why it ranked" text; the list sorts by date, newest first.
- v1 definitions on today's columns (current decision joined by key with the current ruleset, never through the view):
  - **Listed at all:** posting open; lane `engineering`; `us != 'no'`; `citizenship = 0`; `eligibility = 'ok'`; tier
    not `senior`; company not an active no-go and not merged away (use canonical ids as other queries do); posting not
    passed (a `posting_passed` event, or a `pick_passed` event with reason `role`, naming it).
  - **Your level:** `level_ok = 1` (new grad, early career, SDE 1, SDE 2 asking 3 years or fewer), or `level_tier IN
    ('not_stated','open')` at a company whose size is 300 or fewer or unknown (shown tagged "level not stated").
  - **Higher levels:** every other listed posting.
  - **Date:** `posted_on` when present ("posted N days ago"), else the date of `first_seen_at` ("seen N days ago").
  - **Size:** the company's `size` fact (`company_fact`, `num_high` else `num_low`); "big company" over 300.
  - **Flags:** sponsorship `no` shows "Says no sponsorship" (never hides); E-Verify enrolled shows a badge; YC stage shows
    "YC"; a company he contacted shows "You contacted them on DATE" (never hides in v1).
- Default view: your level, last 30 days. Windows 7, 30, 60, 90, any. Order: date newest first, then smaller company,
  then posting id. Keyset paging, 50 rows a page.
- Pass hides one posting and is never a company Not now: `load_passes` (plan cooldown) must not read it;
  `load_passed_postings` must. Go ahead adds the company to today's list as his own pick; only a no-go company, a
  company already on today's list, or one with someone contacted and waiting stops it; size, the 7 day room and a Not
  now cooldown never do. Before the 08:00 plan is built, it records the pick and the build keeps it.
- Alerts: one grouped Mac notice for postings that entered "your level" with `level_ok = 1` and a date of today since
  the last alert; none from 22:00 to 08:00 New York; at most one notice per 15 minutes; each posting once (event key
  `alert:posting:<id>`). Uncertain ("level not stated") rows never alert in v1. Tests never send real notices
  (`OUTREACH_NO_NOTIFY`, and the tick's default notifier is a no-op).
- Claude never calls API write routes on a running server; tests use the test client. Never start, stop or signal a
  process you did not start.
- The page goes through the `craft` skill and its gate; existing tokens and components only.
- No em dashes or en dashes in code, comments, UI copy, docs, commits or the PR body.
- One branch (`DevanshuNEU/job-list-156`), one PR to `master`, body `Part of #156`.

## Review Focus

1. **Speed on the real store** (360,000 postings): `GET /api/jobs` computes in under 1 second cold for the default
   view; check with EXPLAIN QUERY PLAN that the query starts from open postings and uses indexes. Test in Task 1 on a
   seeded store of a few thousand rows, plus a plan check.
2. **A passed posting** disappears at once and after a reload, and its company's other postings stay. Test in Task 3.
3. **Go ahead before 08:00** (no daily list yet) is kept by the plan build and does not make the build stop with
   "already built". Test in Task 3.
4. **The same posting seen in two ticks** alerts once. Test in Task 5.
5. **A posting with no date** sorts by its first sight and is labeled "seen", never "posted today". Test in Task 1.

### Task 1: The job list query

**Files:**
- Create: `outreach/pipeline/joblist.py`
- Test: `tests/test_pipeline_joblist.py` (new)

**Interfaces:**
- Produces: `JobFilters(view: Literal['your_level','higher'] = 'your_level', window_days: int = 30, size:
  Literal['any','small','big','unknown'] = 'any', not_contacted: bool = False, q: str = '')`; `window_days` is one of
  7, 30, 60, 90 or 0 (0 means any).
- Produces: `query(conn, now: str, f: JobFilters, after: str | None, limit: int = 50) -> JobPage(rows: list[JobRow],
  total: int, next_after: str | None, counts: dict[str, int])` where `counts` has `your_level` and `higher` for the
  current window. `after` is an opaque cursor string encoding `(date, size_rank, posting_id)` of the last row.
- Produces: `JobRow(posting_id, title, url, location, level_tag, date, date_kind, age_days, company_id, company_name,
  size, big, says_no_sponsorship, everify, yc, contacted_on)`; `level_tag` is one of `new grad`, `early career`,
  `SDE 1`, `SDE 2`, `level not stated`; `date_kind` is `posted` or `seen`.
- Produces: `passed_posting_ids(conn) -> frozenset[int]` (reads `posting_passed` events and `pick_passed` events with
  reason `role`).
