# Send limit 200 (#227) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** The sender may send 200 emails a day instead of 100, and its pacing fits 200 in a business day.

**Architecture:** One schema migration widens the `send_day.send_limit` CHECK, the config raises the flat limit and
shortens the median gap, and a simulation test proves 200 fit. Phase 1 of the sending plan; phase 2 is per-company
daily limits by company size.

**Spec:** #9 "Send limit 200 ruling (2026-11-12)" and #227.

## Global Constraints

- Flat 200: `ramp_start`, `ramp_floor`, `ramp_ceiling` all 200; `HARD_CEILING` 200; CHECK `BETWEEN 0 AND 200`.
- `gap_median_minutes` 1.5; clip 1 to 25, breaks, window, weekdays, per-company limits and hard blocks unchanged.
- The tests' scratch config keeps the adaptive ramp (20 to 100) and the 2.0 median, so the exact-time tests stand.
- No em or en dashes.

## Review Focus

1. Rows written at 100 before the change lift to 200 (ramp floor), test in Task 2.
2. The rebuild keeps every `send_day` row and its column order, test in Task 1.
3. A scratch-config replacement that stops matching must fail loudly, not silently ship the new value into tests.

### Task 1: Migration 0012
- Create `outreach/store/migrations/0012_send_limit_200.sql`: new table, copy, drop, rename.
- Test `tests/test_send_limit_200.py`: 200 stored, 201 and -1 refused, rebuild keeps rows and columns.

### Task 2: Config and ceiling
- `outreach/sending/config.toml`: ramp values 200, `gap_median_minutes` 1.5. `config.py`: `HARD_CEILING = 200`.
- `tests/__init__.py`: scratch copy maps 200 to the old ramp and 1.5 to 2.0, asserting each line matches once.
- Tests: `test_sending_config` (shipped numbers, 201 refused), `test_sending_ramp` (flat 200, a 100 row lifts).

### Task 3: 200 fits in a day
- `tests/test_send_limit_200.py`: the real sender on a fake Gmail, 100 companies x 3 people across three US zones,
  shipped limit and gaps, sends 200 on one business day.

Deploy: schema change, so `uv run python -m outreach.install` in the live checkout outside 08:30 to 16:30, then
kickstart the API. The sender starts fresh each tick and reads the new config.
