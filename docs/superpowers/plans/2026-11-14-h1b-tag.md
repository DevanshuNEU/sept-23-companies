# H-1B tag on Jobs and Outbox rows Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show a small tag such as "H-1B 2,436, rising" or "No H-1B on record" on every Jobs row and Outbox row, read from `companies.md`. Show only: the sender order does not change.

**Architecture:** `outreach/h1b/lookup.py` reads `companies.md` once per file change (cached by mtime) into a dict keyed by `h1b_key(company name)` and answers `tag_for(name) -> H1bTag | None`. The API adds an optional `h1b` object to `JobRowWire` and `OutboxItem`; the web renders it as a plain (idle) badge. Task 3 of the issue (the MCP read) reuses `lookup.py` in its own PR.

**Tech Stack:** Python 3.14, FastAPI/pydantic wire models, React + TypeScript (web), openapi-typescript schema.

**Spec:** GitHub #9 (job board ruling 2026-11-12, point 7: "H-1B count" and "No H-1B on record" are plain tags), issue #252, `outreach/h1b/__init__.py` for the file format.

## Global Constraints

- Plain tags, never a hide, never a sort change (#9 point 7). The sender, drafter and follow-ups are frozen: no change under `outreach/sending`, `drafting`, `followup_drafter`.
- On-screen copy: sentence case, no dashes, numbers with thousands separators ("2,436"), units always.
- The list is data the user owns: read `<store folder>/h1b/companies.md`, never write it, never copy it into the repo. `OUTREACH_H1B_DIR` overrides the folder (tests).
- No file, no tag: when `companies.md` is missing or unreadable, `tag_for` returns `None` and the row shows nothing (never a false "No H-1B on record").
- The Jobs list read must stay O(rows): one dict lookup per row, the file parsed once per change.

## Review Focus

- File missing or empty: no tag, no error, rows still render (Task 1 test).
- A company name with legal words or case differences ("Microsoft Corporation" vs "Microsoft"): match by `h1b_key` (Task 1 test).
- File replaced by a new build while the API runs: the next read sees it (mtime cache test).
- A line with all zero approvals or a malformed line: skipped, not a crash (Task 1 test).
- A long Outbox row (long company name, Fix link): the tag does not push the summary off the row (web test checks the tag is a `flex-none` sibling; checked by eye in a screenshot).

- Test: `tests/test_h1b_lookup.py`

**Interfaces:**
- Produces: `H1bTag(total: int, trend: str, years: dict[int, int])` frozen dataclass with `.label: str` ("H-1B 2,436, rising") and `.detail: str` ("USCIS approvals by fiscal year: FY2022 1, FY2023 2, ..."); `tag_for(name: str | None) -> H1bTag | None`; `NO_RECORD = "No H-1B on record"`; `h1b_dir() -> Path`.
